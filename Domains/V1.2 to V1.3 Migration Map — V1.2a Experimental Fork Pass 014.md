# V1.2 to V1.3 Migration Map — V1.2a Experimental Fork Pass 014

**Status:** MIGRATION PLANNING / EXPERIMENTAL PREDECESSOR CLASSIFICATION / NO FILE MOVEMENT AUTHORISED

## 1. Core finding

V1.2a defines itself as:

**EXPERIMENTAL / NON-CANONICAL / ISOLATED FROM V1.2**

Its explicit rule is that work inside the fork does not replace, amend, supersede or silently modify V1.2 unless a later explicit research/integration decision occurs.

Therefore the correct migration unit is **not the V1.2a folder**.

V1.2a should become an intact experimental predecessor object under Historical custody.

> **Experimental Fork != Live Architecture**

However:

> **Experimental Origin != Permanent Experimental Status**

Some V1.2a outputs subsequently became validated methods, portable modules, cross-domain architecture or integrated findings. Those later states govern whether the result migrates.

## 2. Whole-fork treatment

Default disposition for the complete V1.2a workspace:

**A1 — ARCHIVE AS INTACT PREDECESSOR EXPERIMENTAL STATE**

This includes by default:
- frozen experimental protocols;
- sampling registers;
- neutral problem packets;
- U1–U8 derivations;
- V1.2 comparison records;
- completed experimental tests;
- cross-case synthesis provenance;
- topology experiments;
- invention-frontier experiments;
- failed/negative tests;
- superseded datasets/models;
- frozen prospective predictions;
- developmental sequencing.

The structure itself is evidence of how the experiment was conducted and should not be reorganised after succession.

## 3. U1–U8 counterfactual experiment

The ten-case experiment asks whether substantially similar civil architecture emerges from the independently derived U1–U8 kernel.

The synthesis reports substantial functional compatibility across the frozen sample while retaining important contamination and sampling limitations.

The consolidated fork explicitly has:

**Canonical effect: NONE**

### Treatment
The experimental corpus remains archived.

Consequential findings required by current V1.3 Research may migrate as bounded summaries/research findings.

**M4 — MIGRATE EXTRACTED FINDING where still current**

Do not migrate the experimental fork as an alternative live constitution.

> **Experimental Convergence != Constitutional Replacement**

## 4. Candidate Outputs to V1.2

This folder is structurally important because it records attempted transitions from experiment to main architecture.

Its contents must be judged by what happened **after** candidacy.

Examples include:
- Civilisational Developmental Topology;

- KCS contestability correction;

The candidate package itself remains experimental/development provenance.

## 14. Legacy-state reconciliation

V1.2a is likely to be a rich source of legacy-status mismatches.

A result may still physically appear as:
- prospective finding;
- candidate architecture;
- hypothesis;
- experimental protocol;
- test output;

while later Concord architecture already incorporated its substance.

Therefore the V1.3 Legacy Architecture State and Graduation Reconciliation Audit should explicitly inspect **V1.2a-derived dependencies**.

Questions:
- Did later V1.2 architecture adopt this result?
- Is there a current authoritative version elsewhere?
- Did the experimental status label become stale?
- Was only part of the result adopted?
- Is a current system depending on a V1.2a object without an explicit graduation/integration record?
- Did the experiment identify a gap that remains genuinely open?

## 16. Historical status

After V1.3 activation, V1.2a should be explicitly understood as a Historical-custodied experimental predecessor state.

It should remain linked to:
- its parent V1.2 context;
- the U1–U8 source lineage;
- any current architecture demonstrably derived from it;
- any later Research programmes continuing its questions.

But Historical custody does not mean copying the entire fork into V1.3.

> **Historical Custody Does Not Require Historical Duplication Inside the Live Architecture.**

## 17. Migration-method finding

V1.2a demonstrates a particularly important succession pattern:

**Experiment**
→ frozen evidence
→ candidate finding
→ validation/integration
→ current architecture
→ experiment remains archived.

The successor should migrate the **right-hand side of that chain where it became live**, not copy the whole chain.

> **Migrate the Integrated Result; Preserve the Experimental State That Produced It.**

This is a specialised application of:

> **Migrate the Living Result; Archive the Developmental Path.**
