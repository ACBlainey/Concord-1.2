# V1.2 to V1.3 Migration Map — Root Architecture Pass 001

**Status:** MIGRATION PLANNING / NO FILE MOVEMENT AUTHORISED

## 1. Principle
V1.2 is a developmental architecture. V1.3 should present the resulting civilisational architecture without cleaning up V1.2 in place.

> **V1.2 preserves developmental provenance; V1.3 presents the resulting civilisational architecture.**

Repository Folder != System != Function != Operational Domain != Authority.

## 9. Architectural Revision 001 — V1.3 as a Living Civilisation

The initial draft retained a root-level Research and Development class as a migration convenience. The target V1.3 architecture should reject that arrangement.

The Concord is no longer best represented as a research project containing a model civilisation. V1.3 should increasingly resemble the structure of the civilisation itself.

> **Research and Development Is a Civil Function of the Research Domain, Not a Peer Structure Beside the Civilisation.**

Active research, development programmes, experiments, candidate architecture and civilisational development work therefore migrate into the **Research domain**, organised into appropriate subdivisions.

When development becomes historically consequential, its provenance is preserved through Historical.

The temporal relationship becomes:

**RESEARCH**
-> investigates / develops / tests now

**OPERATIONAL OR CONSTITUTIONAL HOME**
-> receives graduated architecture where appropriate

**HISTORICAL**
-> preserves development provenance, prior states, failed paths, evidence, decisions and retired material.

> **Research Develops; Domains Operate; Historical Remembers.**

This replaces the earlier proposal for a permanent root-level Research and Development area.

## 10. Portable Modules — Root Visibility with Historical Ownership

Portable Modules require a distinction between **repository visibility** and **architectural ownership**.

They should remain a main root-level folder because participants need to find them easily and because they are intentionally portable across domains and contexts.

They are not a civilisational domain.

Their authoritative custodial owner is **Historical**.

Historical owns preservation of module versions, provenance, graduation history, superseded states, source relationships, interface-regression history and retirement/archive state.

The root Portable Modules folder is therefore a **prominent access surface to a Historical-owned collection**.

Its README must state this explicitly.

> **Root Placement != Domain Status**

> **Discoverability != Architectural Ownership**

The implementation must preserve one clear authoritative custodial relationship and avoid uncontrolled duplicate authorities.

## 11. Revised Root Philosophy

A mature V1.3 root should primarily answer:

> **What are the major structures of this civilisation?**

rather than:

> **How was this research project organised while it was being developed?**

Research is already a domain.
Development is an activity of Research.
Evidence belongs to Research while actively evaluated and Historical when preserved as consequential record.
Development History belongs to Historical.
Legacy copies belong to Historical.
Comparative research belongs to Research.

Therefore much of the current V1.2 organisational superstructure can disappear from the V1.3 root without losing information.

## 14. Migration Consequence

The migration is no longer primarily:

**old research folders -> new cleaner research folders**

It is:

**developmental repository -> living civilisational topology**

Many current V1.2 folders can therefore move conceptually and eventually physically into their domains:

- Governance -> Governance;
- Judiciary -> Judiciary;
- Continuity -> Continuity;
- Economy -> Economy;
- Civil Attention -> Civil Attention;
- Intercivilisational Architecture -> Intercivilisational Relations;
- Participation & Intelligence -> Research;
- Active Development -> Research, with Historical provenance;
- Comparative/Empirical Research -> Research;
- Development History/Legacy -> Historical;
- Portable Modules -> root-visible Historical-owned collection.

This principle should govern the detailed child-level migration pass.
