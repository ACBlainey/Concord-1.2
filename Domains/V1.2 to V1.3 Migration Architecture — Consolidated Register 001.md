# 1. Controlling succession rule

> **Migrate the Living Result; Archive the Developmental Path.**

V1.3 is not a cleaned copy of V1.2.

V1.2 is preserved as a coherent predecessor state.

V1.3 is a successor architecture reconstructed from:
- current civil architecture;
- current constitutional constraints;
- current domains;
- current cross-domain systems;
- current portable modules;
- current applications;
- genuinely active Research;
- current unresolved questions;
- and the minimum dependencies required to understand and operate them.

Development history, completed experiments, superseded states, derivation chains and historical question states remain in predecessor custody unless a live successor dependency requires a bounded extraction.

> **Absence of Later-Method Certification != Absence of Earlier Development or Operational Maturity**

**LEGACY STATUS UNRESOLVED — POST-MIGRATION AUDIT REQUIRED**

Migration should preserve recoverability without manufacturing authority.

**Legacy Architecture State and Graduation Reconciliation Audit**

# 16. Required pre-construction step — Domain Naming and Expectation Audit

The functional topology is frozen at 18, but names may import inappropriate institutional assumptions.

For each domain:

1. state observed persistent civil function;
2. state current/provisional name;
3. identify conventional expectations created by that name;
4. identify functions the name hides;
5. identify functions the name wrongly implies;
6. examine boundaries/interfaces;
7. propose the least misleading name;
8. verify that renaming does not silently alter function or authority.

Special attention:
- Economy and possible broader value coordination;
- Education;
- Health;
- Law;
- Social Support;
- Defence;
- Research;
- Historical;
- Civil Security;
- Culture and Civic Life.

> **Structure Tells Us How Things Relate. Boundaries Tell Us What Things Are Responsible For. Names Tell Us What We Expect Them To Be.**

# 18. Migration conformance tests

V1.3 migration is not complete merely because files were transferred.

It is complete only if:

### Current-state survival
Every required current architecture object survives.

### Ownership
Every live object has a legitimate owner.

### Authority
No migration accidentally grants authority because of folder placement.

### Provenance
Current objects retain enough provenance to locate their predecessor evidence.

### Archive integrity
V1.2/V1.2a remain coherent predecessor states.

### No false graduation
Migration does not promote candidates merely by moving them.

### No false demotion
Later methodology does not erase legacy-established architecture.

### No historical duplication
V1.3 does not carry large provenance bodies merely because they are valuable.

### Active-work survival
Genuinely unfinished work worth continuing is not abandoned.

### Gap honesty
Missing systems remain visibly missing/partial rather than being filled with empty folders or references.

### Discoverability
Humans and AIs can find the live architecture and understand its status.

# 20. Final consolidated finding

The migration analysis shows that V1.2 is not badly organised for the work it performed.

It is organised around **development history and discovery**.

V1.3 has a different purpose.

It should be organised around **what the civilisation currently is**.

That requires a genuine succession rather than a cleanup.

V1.2 should remain legible as the environment in which much of the architecture was discovered, tested and corrected.

V1.3 should become legible as the architecture that survived that process.

> **V1.2 Is the Developmental Predecessor.**

> **V1.3 Is the Domain-Normalised Successor.**

The next required task is the **Domain Naming and Expectation Audit**. Only after that audit should final V1.3 folder names be fixed and successor construction begin.
