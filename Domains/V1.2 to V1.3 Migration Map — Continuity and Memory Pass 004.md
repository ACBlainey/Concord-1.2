# V1.2 to V1.3 Migration Map — Continuity and Memory Pass 004

**Status:** MIGRATION PLANNING / SOURCE-RESOLVED / NO FILE MOVEMENT AUTHORISED

## Governing separation
The current Continuity and Memory area combines four functions: Continuity; KCS/dependency state; Historical provenance; and participant data/metrics.

> **Preserved Information != Recoverable Capability**
> **Knowledge State != Civil Authority**
> **Historical Custody != Operational Ownership**

## Continuity-domain material
**CONTINUITY PROTOCOL V2** and its recovery/verification companion architecture belong in **Domains / Continuity**. Their persistent function is preserving/restoring legitimate civil capability through disruption and change.

Constitutional recognition of continuity may remain referenced by Constitutional Core, but the specialist architecture belongs to the Continuity domain.

Legacy tech continuity should be source-resolved by current status between Continuity and Historical provenance.

## Legacy Ladder
The Legacy Ladder explicitly identifies itself as a portable knowledge and technological continuity module. Its core finding is:

> **The plans are not the technology.**

Recoverability depends on knowledge + people + skills + tools + machines + materials + infrastructure + supply chains + institutions + experience.

**Classification:** Portable Module.
**Destination:** root-visible Portable Modules, Historical-owned.
**Relationship:** Continuity is a principal user of the module, but does not need to physically own the reusable artefact.

> **Domain Function != Portable Representation of a Method Used to Protect That Function**

## KCS
KCS core, companion upgrades and live operational dependency datasets now function across the civilisation.

**Classification:** Cross-Domain Architecture.
**Destination:** Cross-Domain Architecture / Knowledge Control and Change Propagation.

KCS supports live dependency state, material change propagation, back-propagation, current knowledge relationships, and integration with CDT/State Map/Clock.

> **KCS Knows Relationships; It Does Not Inherit the Authority of the Systems It Connects.**

Current datasets stay with live KCS. Superseded states pass to Historical custody:

**LIVE KCS STATE -> SUPERSEDED STATE -> HISTORICAL CUSTODY**

## Why generic Memory disappears
The old label was useful during development, but memory now resolves into precise civil functions:

- **Historical:** what existed, happened, was believed and changed, with provenance and temporal state.
- **KCS:** current knowledge/dependencies and consequential change propagation.
- **Continuity:** recoverable capability.
- **Research:** what is currently being learned/tested.
- **Participant Civil Record:** participant-linked records reconstructable through time under bounded access.

A generic top-level Memory category is therefore unnecessary in V1.3.

## Continuity domain boundary
Continuity should answer:

> **Can this legitimate civil capability survive disruption, handoff, degradation, loss of personnel, technological change or civilisational break—and if not, what is required to restore it?**

Its maturity ladder remains:

**RECORDED -> ACCESSIBLE -> INTERPRETABLE -> ACTIONABLE -> RECOVERABLE -> OPERATIONAL**

Continuity does not own all records, knowledge, infrastructure, people, supply chains or institutions.

> **Continuity of a Capability != Ownership of Every Dependency Required to Reconstruct It**
