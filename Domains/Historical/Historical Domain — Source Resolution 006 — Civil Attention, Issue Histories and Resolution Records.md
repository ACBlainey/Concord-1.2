## 2. Existing Civil Attention Function

The current Concord defines Civil Attention as the common participant-facing mechanism by which civilisation can be caused to:

- notice;
- preserve;
- route;
- examine;
- respond

to possible problems, improvements and collective concerns.

Its participant-facing rule is:

> **Tell the Concord once; the Concord determines who needs to deal with it.**

Its architectural boundary is:

> **Central Visibility ≠ Central Control**

Civil Attention therefore centralises intake, provenance, routing visibility, resolution status and feedback while leaving substantive authority with legitimate domain owners.

This is already highly relevant to Historical because the mechanism generates durable temporal objects from the moment of submission onward.

## 3. Civil Attention Already Contains Explicit Preservation Requirements

The graduated portable module begins:

**Participant Trigger → Common Intake → Receipt → Original Preservation → Provisional Classification ...**

It also establishes:

> **Group for Processing; Preserve Individually for Evidence and Provenance.**

and:

> **Merge for Processing ≠ Erase Individual Provenance.**

The Submission Object exists specifically to preserve what was actually received. Later classification, issue matching, investigation, correction or resolution must not rewrite that original provenance.

Therefore Civil Attention is not merely a live workflow.

It is intrinsically a **provenance-generating temporal system**.

Historical must preserve this property when records cross into historical custody.

## 4. Submission, Issue and Resolution Histories Must Not Collapse Into One Object

Civil Attention explicitly separates:

**Submission Object ≠ Issue Object ≠ Investigation/Examination Object ≠ Finding/Decision Object ≠ Implementation/Remedy Object**

This distinction is critical for Historical.

A future observer may need to reconstruct:

- what a participant actually submitted;
- how the system initially classified it;
- whether it was merged with another issue;
- what evidence later appeared;
- which domains received it;
- what each domain concluded;
- what action occurred;
- what remained unresolved;
- what feedback was returned;
- whether the matter was later challenged or reopened.

Historical custody must therefore preserve object lineage rather than flattening the case into its final resolution.

Candidate principle:

> **Historical Resolution Records Must Preserve the Difference Between What Was Reported, What Was Inferred, What Was Found, What Was Decided and What Was Done.**

This directly parallels the Metrics distinction between measurement, interpretation and correction.

## 5. Closure Is Not Historical Finality

The Central Resolution Record allows overall states including:

- unresolved;
- partially resolved;
- resolved;
- escalated;
- closed subject to reopening.

It also records:

- linked unresolved Issues;
- challenge/review state;
- reopening conditions.

Therefore:

> **Operational Closure ≠ Historical Finality**

A closed Civil Attention issue can remain historically relevant and may later become operationally relevant again.

Historical custody must not erase reopening conditions or the state under which closure occurred.

## 6. Reopening Creates a Temporal Chain, Not a Replacement

The core architecture explicitly permits:

**Challenge / Escalation / Reopening where legitimate**

A reopened case should not overwrite its previous resolved/closed state as though that state never existed.

Historical should be able to reconstruct:

**Original Submission → Original Issue State → Domain Processing → Prior Resolution/Closure → Trigger for Reopening → Reopened State → New Processing → New Disposition**

Candidate principle:

> **Reopening Extends the Historical Chain; It Does Not Rewrite the Earlier Case State.**

This is consistent with Source Resolutions 003–005.

## 7. Central Resolution Record Is a Strong Historical Handoff Candidate

The minimum Central Resolution Record already contains much of what Historical needs:

### Identity and provenance
- Civil Attention Issue ID;
- linked Submission Object IDs;
- input classes;
- original receipt/provenance reference.

### Issue state
- classification;
- Problem State;
- Response State;
- evidence/information state.

### Routing
- Domain Action Objects;
- responsible functions;
- routing reasons;
- transfer/acceptance state;
- Responsibility Resolution objects where needed.

### Dependencies and vitality
- dependency state;
- waiting-for state;
- dependency owner;
- review conditions;
- backstop;
- significant deferral history;
- last material action.

### Domain returns
- processing state;
- bounded status;
- disposition;
- unresolved consequences/dependencies;
- next review condition.

### Overall resolution
- unresolved/partial/resolved/escalated/closed-subject-to-reopening;
- reason;
- linked unresolved issues;
- challenge/review state;
- reopening condition.

### Feedback
- feedback state;
- bounded explanation;
- last communicated material status;
- next expected review/condition.

This makes the Central Resolution Record a natural candidate **historical index/manifest object** after an issue ceases ordinary active processing.

However, it does not mean every linked protected object should automatically transfer into unrestricted Historical storage.

## 8. Historical Should Preserve the Resolution Graph, Not Necessarily Duplicate Every Domain Record

Civil Attention is intentionally cross-domain.

One Issue may create several Domain Action Objects, each processed under a different legitimate authority.

Therefore Historical should not solve preservation by copying all domain records into one giant Civil Attention archive.

A more coherent model is:

**Historical Civil Attention Record = preserved central issue/provenance graph + durable references to domain records + bounded historical state returned by domains + protected linked objects where Historical custody is independently justified**

This preserves reconstructability without destroying domain boundaries.

Candidate principle:

> **Historical Traceability Does Not Require Universal Record Duplication.**

## 9. Domain Returns Are Historically Significant

Civil Attention requires:

> **Every Outbound Route Requires a Return Path.**

and:

> **Domain Completion ≠ Issue Resolution.**

This means the history of a case includes not only final resolution but the distributed domain responses that produced it.

Historical therefore needs to preserve enough information to reconstruct:

- which domains were asked to act;
- whether they accepted responsibility;
- their bounded return state;
- whether a domain completed work;
- whether the overall issue remained unresolved despite domain completion.

This is important because future analysis may reveal failure in routing, ownership, coordination or resolution even when individual domains behaved correctly.

## 10. Responsibility Resolution Is Historical Evidence

The architecture distinguishes:

> **Responsibility Resolution ≠ Substantive Case Resolution.**

Failure to identify an owner must not make an issue disappear.

Responsibility disputes, transfers and unresolved ownership are therefore historically meaningful.

Historical records may need to preserve:

- original routing;
- rejected routing;
- transfer reasons;
- ownership disputes;
- eventual owner resolution;
- periods where no legitimate owner was identified.

This can reveal structural gaps in civilisation that a final case disposition alone would conceal.

## 11. Waiting and Deferral History Must Not Collapse Into a Timestamp

Civil Attention records significant deferral history, dependencies, backstops, review conditions and last material action.

The architecture also distinguishes meaningful action from mere timestamp refresh.

Therefore Historical should preserve material waiting-state history where it affected outcome, harm, delay, escalation or institutional learning.

Candidate principle:

> **Elapsed Time Is Not the Same as Processing History.**

A future historical reconstruction should be able to distinguish legitimate dependency from institutional inactivity.

## 12. Aggregation Creates a Historical Compression Risk

Civil Attention can group multiple submissions into an Issue for processing.

But it explicitly requires individual provenance to survive.

This is especially important historically.

A final record saying:

> 2,000 reports were received

may conceal:

- whether they were independent;
- whether they contained materially different information;
- whether minority reports identified a different failure mode;
- whether later reports added evidence;
- whether contradictory submissions existed.

Civil Attention already separates raw count, independent participants where legitimately knowable, independent evidence, duplicate processing and duplicate information.

Historical must not undo this distinction through archival compression.

Candidate principle:

> **Historical Aggregation Must Not Erase Material Information Delta or Individual Provenance Required for Later Reconstruction.**

This does not require unrestricted retention of participant identity.

Privacy rules remain applicable.

## 13. Petition History Requires Special Care

The current module corrects an important weakness in the V1/V1.1 precursor.

The archived precursor described petitions as gaining greater weight through supporter numbers and treated collective support as affecting review priority.

The graduated current architecture instead establishes:

> **Petition Support ≠ Problem Weight.**

and:

> **Popularity ≠ Truth.**

Support is an attention signal, not proof of truth, severity or entitlement to resources.

This is a useful example of why archived Concord architecture cannot simply be resurrected.

Historical should preserve both:

- the older developmental idea;
- the later corrected/current architecture;

while maintaining their different statuses.

This produces a domain-relevant rule:

> **Historical Preservation of Superseded Architecture ≠ Current Architectural Authority.**

The archive is evidence of development, not a competing live specification.

## 14. Archive Search Produced a Genuine Developmental Finding

The V1 and V1.1 precursor contains the conceptual ancestry of:

- suggestion intake;
- problem reporting;
- petitions;
- traceable status;
- cross-layer routing;
- governance integration;
- feedback.

But several concepts were subsequently refined.

Most importantly, the current architecture separates attention pressure from truth, problem weight, priority and authority much more strongly.

This demonstrates why Historical needs version/provenance status for Concord's own architecture.

Without that status, an old but superficially similar document could be mistaken for current doctrine.

Thus the Civil Attention pass independently strengthens the need for a later dedicated **Constitutional/Architectural Version History** resolution.

## 15. Auditable Status Does Not Mean Public History

Civil Attention states:

> **Auditable Status ≠ Universal Data Access**

and the domain companion requires explicit protected-information boundaries.

Historical therefore cannot infer that a completed Civil Attention record becomes public simply because it is historical.

The existing rule remains:

> **Historical Custody ≠ Public Accessibility**

Civil Attention may preserve public-facing status while linked evidence, identities, judicial records, medical information, security information or other protected content remains restricted.

## 16. Anonymous Inputs Create an Important Historical Boundary

The graduated architecture states that anonymity does not itself make a submission non-actionable and identity does not establish evidentiary sufficiency.

Historical should therefore preserve the epistemic/provenance state that the source was anonymous where material without attempting to reconstruct identity merely to improve the historical record.

Candidate principle:

> **Historical Provenance Should Preserve Legitimate Source Status Without Manufacturing Identity That the Operational System Did Not Possess or Was Not Entitled to Retain.**

## 17. Civil Attention Does Not Give Historical Authority Over the Issue

Civil Attention routes substantive work to legitimate domain owners.

Historical may later preserve the resulting case history.

It does not inherit authority to:

- decide whether the original complaint was true;
- reopen a case;
- alter a domain finding;
- grant a petition;
- impose a remedy;
- reclassify the participant's submission as authoritative fact.

Therefore:

> **Historical Custody of a Civil Attention Case ≠ Authority to Resolve or Reopen the Case.**

Historical may return preserved evidence to a legitimate process when authorised.

The operational system decides what follows.

## 18. Historical Domain Will Need Its Own Civil Attention Companion

The current root architecture requires each domain integration to append a domain companion rather than rewrite the core.

Historical therefore eventually needs:

**Civil Attention Core v1.0 + Historical Domain Companion + Historical services**

The Historical companion will need to specify at least:

- legitimate Historical issue classes;
- what kinds of historical error/omission can be reported;
- evidence/provenance requirements;
- protected historical information boundaries;
- DAO binding;
- correction versus preservation of prior historical state;
- retrieval/revalidation requests;
- retention/forgetting disputes;
- access/disclosure complaints;
- escalation/challenge routes;
- mandatory bounded return states.

However, this companion should be written **after** Historical source resolution is sufficiently mature. Writing it now could prematurely freeze unresolved domain assumptions.

## 19. Civil Attention Can Also Be a Source of Historical Error Correction

A participant may later identify:

- an incorrect historical record;
- missing provenance;
- misclassification;
- improper redaction;
- mistaken identity linkage;
- a missing historical event;
- an incorrect claim about prior civil state.

Civil Attention provides a natural trigger mechanism.

But Source Resolution 004 already established that correction must not falsify the evidential state of the past.

Therefore a Historical correction should likely preserve:

**Prior Historical Record → Challenge → Review/Audit → Correction → Current Historical Representation**

rather than silently replacing the earlier record.

This requires later integration between Civil Attention and Historical correction/versioning.

## 20. ESCP Implication

Civil Attention is especially important to ESCP because it provides a participant-originated route by which dimensions missing from official measurement or institutional observation can enter civil attention.

A historical record of Civil Attention therefore preserves more than complaints.

It can preserve evidence of what the civilisation's formal systems:

- did not initially see;
- did not classify correctly;
- failed to route;
- disputed;
- delayed;
- later accepted;
- later corrected.

Deleting or over-compressing these histories could make later evaluation of the civilisation falsely complete.

However, ESCP does not justify universal permanent retention of all submissions. Privacy, minimisation and forgetting architecture still apply.

The correct inference is:

> **Civil Attention History Can Preserve Evidence of Prior Evaluation-Space Blind Spots; Its Retention Must Still Be Purpose-Bounded and Rights-Constrained.**

↓

## 22. Historical Handoff Threshold Remains Unresolved

Civil Attention gives us better candidate objects for handoff but does not fully answer **when** transfer occurs.

Possible triggers include:

- issue resolved;
- issue closed subject to reopening;
- expiry of an operational appeal/review period;
- transition to long-term monitoring only;
- domain record becoming superseded;
- retention-state decision;
- explicit historical significance determination.

But no universal threshold has yet been source-resolved.

Therefore the general Historical archival threshold remains open.

## 25. Archive-Stratum Result

The V1/V1.1 search was useful and should now become standard procedure.

For this pass it showed:

1. the core bottom-up attention concept existed before V1.2;
2. current V1.2 architecture materially refined it;
3. some older assumptions, especially petition/support weighting, should not be imported as current rules;
4. archived versions are valuable evidence of architectural development even when superseded.

Accordingly, future Historical passes should continue the search order:

**V1.2 named system → V1.2 adjacent/interfaces/dependencies → V1.1 archive → V1 archive → unresolved classification**

while preserving source status.

## 26. Current Finding

Civil Attention strongly confirms the emerging Historical model.

Historical is not merely a destination for final documents.

It must be capable of preserving **process history**:

- original input;
- changing classification;
- evidence development;
- routing;
- responsibility;
- waiting;
- domain responses;
- decisions;
- remedies;
- feedback;
- challenge;
- reopening;
- correction.

The most important object is therefore not necessarily the final resolution text.

It is the **traceable temporal relationship among the objects that produced the resolution**.

Civil Attention also demonstrates why Historical needs status-aware preservation of Concord's own development. The V1/V1.1 precursor remains historically valuable precisely because parts of it are no longer the current architecture.
