# Concord Domains

**Project:** The Concord
**Status:** DOMAIN DEFINITION AREA / CORRIGIBLE
**Date:** 25 September 2026

## Purpose

This root area defines the Concord's functional domains and records which systems, responsibilities, authorities and interfaces belong to each domain.

A domain is not defined merely by repository location.

> **Repository Folder ≠ System ≠ Function ≠ Operational Domain ≠ Authority**

Domains should be derived from coherent civil functions, responsibility boundaries and legitimate authority rather than inherited accidentally from the repository tree.

Each domain definition should ultimately identify its civil function and purpose; responsibilities and boundaries; systems and mechanisms it contains or composes; information/data it owns operationally or custodially; legitimate authorities and authority limits; dependencies and interfaces; protected-space/access requirements; Civil Attention interface; review interfaces; and unresolved ownership questions.

## Initial Domain

The first domain being formally resolved is `Historical/`.

Historical is the first worked domain-definition exercise because its function is visible across multiple existing Concord systems while not corresponding cleanly to any single repository folder.

The method and lessons from resolving Historical may later inform definition of the remaining Concord domains.
