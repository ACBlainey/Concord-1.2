# 1. Invention Position

**IF-002 — Failure-Safe Civil-State Migration**

Required capability:

> An atomic or failure-safe civil-state migration protocol that transfers the minimum necessary contact/communication state between replaceable providers without loss, duplication, silent omission, surveillance expansion or interruption of legal/civil obligations.

# 2. State That May Require Continuity

The problem is not wholesale account copying. Relevant state may include:

- current reachability status;
- pending authoritative communications;
- acknowledgements and disputed delivery states;
- unresolved response obligations;
- participant modality/accessibility requirements;
- bounded identity linkage;
- provenance necessary to establish continuity;
- active challenge/review state.

Only state necessary to preserve the civil function should migrate.

# 3. Frozen Constraints

C1 persistent civil identity survives migration;
C2 migration does not require transfer of unnecessary historical provider data;
C3 pending authoritative communications cannot silently disappear;
C4 the same obligation must not silently become duplicated into multiple active consequences;
C5 the old provider cannot indefinitely veto migration;
C6 the new provider cannot acquire authority merely by receiving state;
C7 there must be a verifiable transition point or transition condition;
C8 interrupted migration must recover to a known civil state;
C9 disputed state must remain visibly disputed;
C10 provenance must survive without becoming a universal activity history;
C11 participant accessibility/modality requirements must survive where relevant;
C12 deadlines/consequences must account for migration-caused unreachability;
C13 migration must support provider failure as well as planned transfer;
C14 rollback/recovery must not restore obsolete obligations as if current;
C15 future provider/transport types must be supportable without redefining civil identity.

# 4. Failure Tests

F1 old provider disappears mid-transfer;
F2 new provider fails before completion;
F3 both providers claim authoritative control;
F4 neither claims responsibility;
F5 pending notice exists during migration;
F6 participant response is sent during transition;
F7 duplicate copy creates duplicate consequence;
F8 malicious provider withholds state;
F9 corrupted/incomplete migration package;
F10 participant disputes transferred record;
F11 privacy leak from unnecessary history transfer;
F12 migration between different modalities/substrates;
F13 emergency migration without ordinary participant interaction;
F14 long network partition during migration;
F15 later audit must determine what happened.

# 5. Success Pattern

Civil State A
→ Bounded Transfer State
→ Verifiable Handover
→ Civil State B

while preserving:

Identity + Pending Obligations + Disputes + Necessary Provenance

and avoiding:

Silent Loss + Duplicate Authority + Provider Lock-In + Excess Data Transfer.
