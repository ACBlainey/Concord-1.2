# Developmental Maturity Map 001 — First Cross-Generation Relational Audit

**Status:** V1.2a EXPERIMENTAL / FIRST EMPIRICAL MAP  
**Date:** September 2026  
**Canonical effect:** NONE  
**Protocol dependency:** *Prospective Hypothesis — Developmental Maturity Mapping and Abstraction-Layer Levelling* was frozen before this audit.

# 1. Purpose

This is the first empirical attempt to represent uneven architectural development across Concord systems.

It does **not** assign a quality score to documents.

It asks a narrower question:

> Where a system activates a relation in the currently frozen relational grammar, is that relation explicit, distributed, partial, not established, inapplicable, or representation-uncertain?

The first sample deliberately contains systems known from project development history to occupy different developmental generations, plus strong negative controls.

# 2. Evidence Boundary

Repository commit dates are not treated here as reliable creation dates because material has been migrated and reorganised across Concord versions.

Developmental generation is therefore recorded conservatively as:

- **EARLIER** — known to originate in an earlier phase of Concord development;
- **LATER** — known to belong to substantially later recursive development;
- **VERY RECENT** — current Layer-Zero / recent wrapper development;
- **UNRESOLVED** — chronology not safely established.

The chronology field is contextual evidence, not proof of maturity.

# 3. Tested Relation

The first map focuses on the relation exposed by CH001 and CH002:

Assessment / Classification
+ Material Participant Consequence
→ Inspectability
+ Context where relevant
+ Contestability
+ Review
+ Correction / Reconsideration
+ Downstream Consequence Propagation
+ Provenance.

This is deliberately narrow. A full maturity map will require additional relational families.

# 5. Source-Grounded Notes

## M01 — KCS

KCS explicitly distinguishes domain-specific demonstrated reliability from universal worth and allows reliable contribution to lead to greater access:

**Observe → evaluate → contribute → demonstrate reliability → receive greater access → contribute further.**

It strongly develops provenance, challenge and correction of knowledge itself.

The currently identified weakness is narrower: no complete participant-facing path was verified from:

KCS consequential classification
→ participant challenge
→ review
→ correction
→ downstream KCS access/standing revision
→ provenance.

This remains CH001.

## M02 — Attractor & Induction

The protocol explicitly states that participation is voluntary, reversible and progressive.

It also states:

**Participation should increase progressively as mutual understanding, demonstrated reliability and reciprocal benefit increase.**

Collaborator status involves expanded access.

Branch placement is revisable and participants receive meaningful feedback on progression where appropriate.

However, the dedicated CH002 source test did not establish an explicit path from a disputed reliability/progression assessment through correction and downstream reconsideration.

Reversibility of participation does not itself provide contestability of a consequential progression judgement.

## M03 — Citizen Data Ownership / Contestable Metrics

This architecture provides the general function apparently missing as an explicit interface in M01/M02:

- access to significant personal records/classifications;
- inspectability of consequential models;
- challenge to data, classifications, interpretations and models;
- correction and provenance;
- downstream improvement of metrics;
- escalation for serious unresolved disputes.

This is an important solution-source candidate.

## M04 — Participant Digital Twin

The Digital Twin is explicitly defined as a purpose-limited, inspectable and revisable representation subordinate to the real participant.

It includes:

**PARTICIPANT CHALLENGE → SOURCE REVIEW → CORRECTION**

and separately develops interpretive contestability, participant context and model mismatch.

It states that consequential interpretation should be understandable enough to be meaningfully challenged.

This is a strong example of the tested relation appearing inside initial system design rather than needing to be supplied retrospectively.

## M05 — Supported Decision-Making and Capacity

This system makes capacity:

- non-binary;
- decision-specific;
- context-sensitive;
- reassessable;
- reviewable;
- contestable.

Significant capacity restrictions may involve participant challenge and judicial review.

The stronger the restriction, the stronger the review requirement.

The participant should understand how a determination can be challenged and when it will be reviewed.

This is an especially strong negative control because the consequence — loss or transfer of decision authority — is severe and the architecture correspondingly strengthens review.

## M06 — Minimum Necessary Capability

This architecture explicitly develops:

Purpose
→ Function
→ Need
→ Minimum Sufficient Capability
→ Bounded Exercise
→ Review
→ Termination or Re-Justification.

Capability provenance asks, among other things:

**How can it be challenged?**

Review burden scales with capability consequence.

The architecture includes narrowing, redistribution, redesign, termination and re-justification, and consequential assumed authority can trigger automatic independent review.

This is another strong negative control: the topology should not flag the tested relation as missing here.

# 6. First Result

The first cross-generation sample separates into two groups.

Earlier systems in this sample:

M01 KCS
M02 Attractor / Induction

show the consequential-assessment trigger while lacking a verified complete local/interface path for participant contestability and correction propagation.

Later/recent systems in this sample:

M03 Contestable Civilisational Metrics
M04 Participant Digital Twin
M05 Supported Decision-Making
M06 Minimum Necessary Capability

contain increasingly explicit forms of the relation.

Observed sample pattern:

Earlier sampled systems
→ consequential classification exists
→ complete contestability/correction interface not verified.

Later sampled systems
→ same structural problem recognised
→ contestability/review/correction/provenance increasingly explicit.

This is **supportive of** the frozen Temporal Propagation Gap hypothesis.

It is not yet proof of a corpus-wide chronological gradient.

# 7. Important Negative-Control Result

The detector does not classify every system with assessment, prediction or allocation as requiring the same participant-level interface.

The recent System-Steering and Predictive Resource Allocation architecture was separately inspected during candidate discovery.

It explicitly places allocation primarily at aggregate/system level and explicitly excludes determining individual eligibility from its scope.

Therefore:

Aggregate prediction / system allocation
≠ automatically
individual consequential classification.

This supports the trigger-condition approach:

Material participant consequence must actually be established before the participant-contestability relation is required.

The sample continues to support:

Consequential Participant Assessment
→ Legibility
→ Context
→ Contestability
→ Review
→ Correction
→ Downstream Reconsideration
→ Provenance.

The important result is that later systems instantiate this relation in different domains without requiring identical institutions.

This is consistent with:

Shared Relational Grammar
+ Domain Constraints
→ Domain Architecture.

# 10. Temporal-Propagation Interpretation

The current evidence is consistent with the following developmental process:

Earlier System
→ later Concord learns stronger contestability/correction architecture
→ newer systems incorporate lesson
→ earlier system remains structurally older until recursively revisited.

If later tests continue to show this pattern, the primary maintenance problem is not failure to learn.

It is incomplete propagation of learning across previously developed architecture.

# 13. ESCP

This map is intentionally incomplete.

Six mapped systems cannot establish the maturity state of the Concord.

Absence in this matrix is not absence in the civilisation.

The map should expand by source verification, not by inference from document age or directory location.

The purpose of this first map is to determine whether the proposed representation can carry useful developmental information.

On the first narrow test, it can.
