# 1. Purpose

The U1–U8 experiment generated ten first-order architectural positions:

- A1 — Bounded, Purpose-Linked and Contestable Information
- A2 — Function-Bounded, Corrigible and Regenerative Authority
- A3 — Evidence-Constrained, Reparative and Correctable Adjudication
- A4 — Provisional, Plural and Correctable Knowledge
- A5 — Adaptive Sufficiency, Agency and Stewardship
- A6 — Agency-Preserving Developmental Support
- A7 — Substrate-Neutral, Capability-Bounded Participation
- A8 — Adaptive Functional Continuity and Regenerative Recovery
- A9 — Necessity-Bounded Emergency Bridge
- A10 — Plural Coexistence and Interoperability

A preliminary correspondence check indicates that canonical V1.2 has recognisable system/domain counterparts to all ten positions.

This document does **not** inspect those counterparts further.

Instead it moves outward one abstraction level and asks:

> When A1–A10 coexist as parts of one civilisation, what additional civilisational functions become necessary because the systems interact?

The purpose is to derive those Level-1 nodes before testing whether canonical V1.2 contains them.

---

# 2. Derivation Rule

Let:

\[
L_0=\{A_1,...,A_{10}\}.
\]

For interacting systems \(A_i,A_j\), derive a candidate Level-1 node only where their coexistence creates a requirement that:

1. is civilisationally consequential;
2. cannot be adequately assigned to only one root system without distorting its function;
3. recurs or plausibly applies across multiple root-system boundaries;
4. requires persistent architecture rather than a one-off decision;
5. is supported by the existing U1–U8 relational grammar.

Thus:

\[
L_1=\Phi(L_0,E_0,U)
\]

where \(E_0\) is the set of materially relevant cross-system interactions and \(U\) is the ethical kernel.

A universal relation or constraint is not automatically a system node. The candidate must perform a distinct cross-system civilisational function.

---

# 3. Candidate L1-01 — Civilisational Interface Coordination

## Trigger

Multiple legitimate systems must exchange decisions, state, requests, evidence or consequences without silently acquiring authority over one another.

Examples of generating intersections include:

- governance ↔ adjudication;
- epistemics ↔ governance;
- participation ↔ governance;
- resources ↔ participation;
- continuity ↔ every critical system;
- emergency ↔ ordinary authority;
- intercivilisational interfaces ↔ internal civil systems.

## Required function

Maintain explicit, bounded and interpretable interfaces between independently legitimate systems.

## Distinctive role

This is not ordinary governance. It is the architecture of **how systems meet**.

It must preserve:

- ownership boundaries;
- input/output meaning;
- authority boundaries;
- dependency visibility;
- failure states;
- correction propagation;
- interface replacement.

### Candidate node

**L1-01 — Civilisational Interface Coordination**

---

# 4. Candidate L1-02 — Cross-System Dependency and Criticality Management

## Trigger

A system can appear locally healthy while depending on another system whose failure disables it.

Multiple systems may also appear redundant while sharing one hidden upstream dependency.

## Required function

Represent and manage material dependencies among civilisational functions.

This includes:

- dependency ownership;
- criticality;
- upstream/downstream exposure;
- correlated dependency;
- alternative paths;
- dependency failure;
- recovery ordering;
- replacement.

### Candidate node

**L1-02 — Cross-System Dependency and Criticality Management**

---

# 5. Candidate L1-03 — Civilisational State and Transition Representation

## Trigger

A civilisation composed of changing systems requires some way to distinguish:

- present state;
- historical state;
- proposed state;
- unresolved state;
- superseded state;
- transition;
- branch/divergence;
- recovery state.

Without this, different systems can operate from incompatible assumptions about the civilisation they jointly constitute.

## Required function

Maintain a provenance-aware, non-sovereign representation of consequential civil state and material transitions.

The representation must not make the map authoritative merely because it is a map.

### Candidate node

**L1-03 — Civilisational State and Transition Representation**

---

# 6. Candidate L1-04 — Cross-System Contestability and Correction Propagation

## Trigger

A decision or classification originating in one system may create consequences in several others.

Correcting the source without correcting downstream consequences leaves the civilisation materially wrong.

## Required function

Provide routes by which consequential challenge, review and legitimate correction can propagate across system boundaries.

Generic relation:

\[
Source\ Error
\rightarrow Review
\rightarrow Correction
\rightarrow Downstream\ Reconsideration.
\]

This does not require one universal appeals body. It requires a civilisational correction pathway across system interfaces.

### Candidate node

**L1-04 — Cross-System Contestability and Correction Propagation**

---

# 7. Candidate L1-05 — Civilisational Provenance and Learning

## Trigger

A multi-system civilisation changes through decisions, failures, corrections, replacements and discoveries.

If these remain local, other systems cannot reliably distinguish:

- current from obsolete reasoning;
- failure from success;
- correction from erasure;
- inherited assumption from validated result.

## Required function

Preserve enough cross-system provenance for consequential civilisational learning.

Generic relation:

\[
Decision
\rightarrow Outcome
\rightarrow Review
\rightarrow Correction
\rightarrow Provenance
\rightarrow Reuse/Learning.
\]

### Candidate node

**L1-05 — Civilisational Provenance and Learning**

---

# 8. Candidate L1-06 — Recursive Oversight and Meta-System Constraint

## Trigger

Once systems review, measure, coordinate, map or correct other systems, those meta-functions themselves acquire consequential capability.

The relational grammar requires:

\[
MetaAuthority\rightarrow MetaConstraint.
\]

## Required function

Ensure that cross-system oversight, measurement, coordination and development mechanisms remain themselves bounded, inspectable, contestable, correctable and replaceable.

### Candidate node

**L1-06 — Recursive Oversight and Meta-System Constraint**

---

# 9. Candidate L1-07 — Civilisational Development and Gap Response

## Trigger

The coexistence of multiple systems generates needs and failures that cannot be predicted exhaustively at design time.

Recognising a gap is insufficient if there is no route from recognition to development.

## Required function

Convert validated civilisational needs and capability gaps into bounded development processes.

Generic pathway:

\[
Need
\rightarrow Gap
\rightarrow Development\ Opportunity
\rightarrow Candidate
\rightarrow Test
\rightarrow Adoption/Reject
\rightarrow Observation.
\]

This node must preserve plural search and must not give the development mechanism sovereignty over the civilisation.

### Candidate node

**L1-07 — Civilisational Development and Gap Response**

---

# 10. Candidate L1-08 — Cross-System Continuity and Regeneration Coordination

## Trigger

A8 provides continuity as a root architecture, but a civilisation containing many mutually dependent systems creates a higher-order problem: restoration sequence and cross-system regeneration.

Independent recovery plans can conflict or fail because prerequisites are missing.

## Required function

Coordinate recoverability of civilisational functions across system boundaries, including:

- critical-function identification;
- prerequisite ordering;
- minimum recoverable configuration;
- graceful degradation;
- state handover;
- replacement;
- restoration of correction and generative capability.

### Candidate node

**L1-08 — Cross-System Continuity and Regeneration Coordination**

This is distinct from preserving one system. It concerns recovery of the interacting civilisation.

---

# 11. Candidate L1-09 — Civilisational Boundary, Translation and Reachability

## Trigger

A plural multisubstrate civilisation contains participants and systems with different representations, capabilities, modalities and potentially incompatible internal models.

A10 addresses intercivilisational interoperability, while A7 addresses participation. Their interaction with A1–A9 creates an internal civil reachability requirement.

## Required function

Ensure that consequential civil functions remain meaningfully reachable across legitimate differences without requiring identical internal representation.

This includes:

- semantic translation;
- modality translation;
- loss visibility;
- accessibility;
- authoritative meaning preservation;
- bounded identity/reference;
- non-gatekeeping reachability.

### Candidate node

**L1-09 — Civilisational Boundary, Translation and Reachability**

---

# 12. Candidate L1-10 — Civilisational Topology / Integrated Structural Representation

## Trigger

A1–A10 plus L1-01–L1-09 form a network rather than a list.

No individual system can reliably determine whole-civilisation structure from its local view.

## Required function

Maintain an explicit representation connecting:

- ethical roots;
- required functions;
- system ownership;
- interfaces;
- dependencies;
- participants;
- consequential effects;
- failure pathways;
- correction routes;
- continuity paths;
- development state;
- provenance.

The representation supplies visibility, not sovereignty.

### Candidate node

**L1-10 — Civilisational Topology / Integrated Structural Representation**

---

# 13. Candidate L1-11 — Developmental State and Civilisational Levelling

## Trigger

Document age, revision count and local sophistication do not establish architectural maturity.

Different systems can develop unevenly, and advanced features can coexist with unresolved lower-level requirements.

## Required function

Represent the warranted developmental state of each required system independently of document iteration and identify civilisation-level bottlenecks.

For system \(S_i\):

\[
D(S_i)\neq VersionCount(S_i).
\]

Contiguous maturity is determined by applicable architectural requirements, while higher feature exposure is recorded separately.

At civilisation scale, development priority depends not merely on the least-developed document but on the consequential upstream bottleneck.

### Candidate node

**L1-11 — Developmental State and Civilisational Levelling**

---

# 14. Candidate L1-12 — Cross-System Failure, Resilience and Safeguard Recursion

## Trigger

Failures can propagate between systems. Safeguards can themselves create dependencies, concentration, capture or new failure modes.

## Required function

Represent and test:

\[
Architecture
\rightarrow Failure
\rightarrow Safeguard
\rightarrow SafeguardFailure
\rightarrow Revision.
\]

The function must distinguish:

- local failure;
- propagated failure;
- correlated failure;
- safeguard failure;
- accepted residual risk;
- unresolved analysis.

### Candidate node

**L1-12 — Cross-System Failure, Resilience and Safeguard Recursion**

# 15. Nodes Deliberately Not Promoted

The following recurring relations are important but are **not** presently promoted to independent L1 system nodes:

- bounded scope;
- standing;
- anti-domination;
- review;
- correction;
- temporal revision;
- replaceability;
- uncertainty;
- minimum necessary capability.

These remain general architectural constraints or relation families unless later evidence shows that they require an independent civilisational owner.

Likewise, specific mechanisms such as voting systems, courts, currencies, metrics, databases or protocols are not root/topological nodes merely because they may implement one.

# 17. Comparison Protocol

Only after this file is frozen should canonical V1.2 be inspected for coverage of L1-01 through L1-12.

Each node must be classified:

- **PRESENT-EXPLICIT**
- **PRESENT-DISTRIBUTED**
- **INTERFACE-SATISFIED**
- **PARTIAL**
- **CANDIDATE-ABSENT**
- **UNKNOWN**
- **DISPUTED**

A candidate absence is not a confirmed gap.

For PARTIAL, CANDIDATE-ABSENT, UNKNOWN or DISPUTED:

1. perform whole-corpus source resolution;
2. resolve the architectural unit and legitimate owner;
3. distinguish local omission from civilisational omission;
4. apply ESCP;
5. classify any surviving deficit by gap type;
6. do not invent a solution during the coverage pass.

Portable Modules are excluded as primary evidence that canonical V1.2 occupies a predicted node. They may subsequently be searched as secondary solution/reference material.
