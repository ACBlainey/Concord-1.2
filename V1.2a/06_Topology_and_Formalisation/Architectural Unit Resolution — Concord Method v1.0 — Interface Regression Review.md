# Architectural Unit Resolution — Concord Method v1.0 — Interface Regression Review

**Status:** INTERFACE REGRESSION REVIEW — PASS
**Subject:** Architectural Unit Resolution — Concord Method v1.0
**Date:** 24 September 2026

## Purpose

This review tests whether promoting AUR from frozen experimental source into current corrigible Concord methodology is compatible with CRADP, State and Maturity Mapping, KCS, Active Development and ESCP.

The test is architectural. It does not claim universal empirical validity.

## 1. CRADP interface

CRADP already requires:

Candidate Deficit
→ Source Resolution
→ Ownership Resolution
→ Dependency Trace
→ Gap Classification.

It explicitly warns:

- MissingLocalCapability does not imply local invention;
- external capability requires sufficient interface;
- source search precedes development;
- distributed fragments are a possible source-resolution outcome;
- no verified mechanism found within searched scope is not universal absence.

AUR does not replace this cycle. It formalises a previously under-specified gate between candidate deficit/source resolution and gap classification:

Candidate Deficit
→ Source Resolution
→ **AUR Unit / Family Resolution**
→ Ownership / Dependency Resolution
→ Gap Classification.

AUR's C6 interface gap aligns with CRADP Integration Gap.

AUR's C7 family-level structural gap aligns with CRADP Structural Gap, while adding an explicit resolved-family/search-scope boundary.

AUR's C5 representation gap aligns with CRADP Representation Gap.

AUR's C3/C4 external/distributed satisfaction strengthens CRADP's False Positive / REUSE route.

No CRADP development, prediction-freeze, intervention, retest or recursive-method function is absorbed by AUR.

**Result: PASS**

### Bounded CRADP follow-up

CRADP v0.1 remains an experimental protocol. If/when CRADP itself is promoted or revised, its operating cycle should explicitly name AUR as the pre-gap unit/family-resolution gate rather than requiring future instances to infer the relationship.

This is not a blocking defect in AUR.

## 2. Civil State Map / SMM interface

The integrated SMM companion already requires assessment-unit resolution and source resolution before promoting CANDIDATE_ABSENT to a true architectural gap.

AUR supplies a more precise method for that task.

Compatibility is strong:

- SMM's assessment-unit boundary maps directly to AUR unit resolution;
- SMM's local/distributed/interface supplier search maps to AUR family closure;
- SMM's CANDIDATE_ABSENT / UNKNOWN boundary is preserved;
- AUR C6/C7 prevents SMM from treating interface failure as absence of capability;
- AUR C3/C4 prevents a partial document from lowering family-level maturity where supply is genuinely external/distributed;
- AUR's diagnostic closure does not force SMM sufficiency.

> **AUR Classification ≠ SMM Maturity or Sufficiency State**

AUR resolves what architecture/function is being evaluated; SMM evaluates represented maturity/sufficiency/consequence.

**Result: PASS**

## 3. KCS interface

KCS records dependency, provenance, change and represented state. AUR may consume those records as evidence for family membership, historical/current status and interface relations.

The promoted AUR preserves:

> **No Recorded Dependency ≠ No Dependency**

Therefore KCS absence cannot be used as proof of architectural absence.

The current/historical/candidate distinction is compatible with KCS preservation and supersession semantics.

AUR's requirement to record family-membership evidence improves provenance without making KCS sovereign over family membership.

AUR does not alter KCS records or make dependency centrality authoritative.

**Result: PASS**

## 4. Active Development interface

Active Development exists to move an idea/problem through disciplined examination rather than convert an observation directly into architecture.

AUR strengthens the point before an apparent architectural omission becomes a development problem:

- local omission may route to NO CHANGE / REUSE;
- representation gap may route to representation correction;
- C6 may route to interface development;
- owner immaturity may route through CRADP to legitimate-owner development;
- C7 may justify bounded structural-development candidacy;
- C9 should normally preserve HOLD/source-resolution need.

AUR does not itself promote sketches, create Development Notes, establish canonical status or authorise invention.

This is compatible with the Active Development rule:

> **Interesting idea ≠ established fact**

and its provenance/promotion discipline.

**Result: PASS**

## 5. ESCP interface

AUR directly operationalises ESCP at architectural-unit scale.

The strongest regression risk would be converting bounded family closure into a claim of global completeness.

The promoted method explicitly prevents this:

> **No Adequate Mechanism Found Within Resolved Family/Search Scope ≠ No Mechanism Exists Anywhere**

C7 is scope-bound.

C9 remains available where source resolution is insufficient.

Future, historical and unresolved neighbours cannot be silently treated as current satisfaction.

Thus AUR simultaneously prevents:

- false positive structural gaps caused by local incompleteness;
- false negative gap closure caused by merely naming an external neighbour;
- universal absence claims from bounded search.

**Result: PASS**

## 6. Authority regression

AUR remains a diagnostic method.

It does not:

- grant civil authority;
- decide whether a normative rule is legitimate;
- determine governance jurisdiction;
- authorise development;
- make KCS dependency state sovereign;
- turn unit typing into hierarchy;
- turn source completeness into certainty.

**Authority regression: NONE OBSERVED**

## 7. Epistemic regression

Preserved:

- Document ≠ System;
- Missing locally ≠ missing architecturally;
- Named neighbour ≠ adequate interface;
- Future reference ≠ current dependency;
- Diagnostic closure ≠ functional satisfaction;
- bounded search ≠ complete evaluation space;
- unknown remains a legitimate state.

**Epistemic regression: NONE OBSERVED**

## 8. Complexity / duplication regression

AUR duplicates some CRADP source-resolution concepts deliberately, but at a narrower diagnostic resolution.

This is not architectural duplication because:

- CRADP owns the larger recursive development cycle;
- AUR owns the pre-gap unit/family-resolution gate;
- SMM owns maturity/sufficiency synthesis;
- KCS owns represented dependency/provenance state;
- Active Development owns development progression.

The ownership boundary is legible.

**Duplication regression: NONE OBSERVED**

## 11. Evidence boundary

The evidence supporting promotion includes two blind portable tests with 32/32 frozen predictions materially confirmed.

That supports transfer and source reintegration.

It does not prove:

- universal applicability;
- complete source recovery;
- zero false positives/negatives;
- superiority to all alternative architectural-analysis methods;
- or implementation correctness in every future Concord audit.

## Conclusion

AUR integrates cleanly into the current Concord methodological architecture.

It improves the transition from apparent local deficit to justified gap classification without displacing CRADP, SMM, KCS, Active Development or ESCP.

The promoted AUR method is therefore architecturally integrated.
