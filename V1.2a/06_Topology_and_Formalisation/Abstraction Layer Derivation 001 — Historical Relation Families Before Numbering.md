**Status:** V1.2a PRE-LEVEL DERIVATION / FROZEN BEFORE SYSTEM ASSIGNMENT

# 1. Purpose

The abstraction-level model requires actual layer content before any system can be assigned an AL.

This file deliberately does **not** assign AL numbers yet.

Instead it extracts recurrent relation families from the preserved developmental sequence and asks which represent genuinely later abstraction rather than merely additional domain detail.

This prevents constructing a convenient L1–L10 ladder after seeing desired system scores.

# 2. Evidence Used

The derivation is grounded in the already preserved V1.2a development sequence, including:

- Relational Grammar v1.0;
- Developmental Maturity Maps 001 and 002;
- developmental dependency topology;
- Clock/CRSTL development;
- KCS/KMDI development;
- State Map/CCSSL development;
- Recursive Self-Development Event 001.

The purpose is not to reconstruct the entire historical chronology of every Concord paper.

It is to identify abstraction families that the experiment has already demonstrated as distinct developmental additions.

# 3. Candidate Relation Family RF-A — Functional Coherence

A civil system requires a legible function.

Core relations:

Reality/Need
→ Evidence
→ Legitimate Function.

The system must make sufficiently clear:

- what need/reality it responds to;
- what function it performs;
- what outputs/consequences it produces;
- what domain it belongs to.

Without this, later constraints cannot reliably attach to the system.

# 4. RF-B — Bounded Authority and Scope

Capability/function does not create unlimited authority.

Relations include:

Legitimate Function
→ Bounded Scope.

Capability
NOT→ General Authority.

Existing Legitimacy(scope a)
+ New Scope b
NOT→ Legitimacy(scope b).

This family introduces explicit boundary reasoning around power/capability.

# 5. RF-C — Participant Consequence and Anti-Domination

Where participants are materially affected:

MaterialConsequence
→ Standing
+ Agency
+ Accessible Challenge.

Where asymmetry exists:

MaterialAsymmetry
→ AntiDomination
+ StrongerReview.

This family includes the later-observed consequential-classification relation:

Assessment
+ Material Participant Consequence
→ Inspectability
+ Context
+ Contestability
+ Review
+ Correction
+ Downstream Reconsideration
+ Provenance.

# 6. RF-D — Correction, Temporal Revision and Replaceability

Systems must not merely operate; they must be correctable across time.

Relations include:

Review
→ Correction
→ Revision
→ Learning.

ContinuityNeed(Function)
→ Preserve(Function)
AND Allow(Replace(Form)).

Escalation
NOT→ PermanentHigherAuthority.

This family adds termination, re-justification, replacement and temporal correction.

# 7. RF-E — Provenance and Learning

Correction/failure must alter future civil knowledge.

Relations include:

Source
→ Provenance
→ Decision
→ Implementation
→ Outcome
→ Review
→ Correction
→ Continuation/Supersession.

Learning must preserve enough history to distinguish correction from erasure.

# 8. RF-F — Recursive / Meta-System Constraint

Systems that map, measure, review, govern or correct other systems become subject to the relevant constraints themselves.

MetaFunction(X)
→ ApplyRelevantGrammar(X,X).

MetaAuthority
→ MetaConstraint.

This family prevents oversight, metrics, maps and development systems from exempting themselves.

# 9. RF-G — Cross-System Dependency and Ownership

A local missing capability does not necessarily justify a local subsystem.

MissingLocalCapability(A,x)
NOT→ Invent(A,x).

Instead:

Need(A,x)
→ IdentifyLegitimateOwner(B,x)
→ Assess B
→ Reuse / Integrate / Develop / Hold / Invent.

Requirements propagate upstream.

Capabilities propagate downstream.

This family distinguishes structural gaps, integration gaps and developmental dependency gaps.

# 10. RF-H — State, Transition and Consequence-Relative Ordering

Civil development requires representation of changing state without assuming one universal total order.

Relations include:

State(T0)
→ MaterialTransition
→ State(T1).

Timestamp(A)<Timestamp(B)
NOT→ MaterialPrecedence(A,B) for every function.

DifferentTimestampSystems
NOT→ InvalidEvent.

Legitimate concurrency, branch state, unknown-but-material ordering and correction/supersession must be representable.

# 11. RF-I — Persistent Material Dependency Representation

Dependencies themselves become civil knowledge objects.

A material dependency requires bounded representation of:

- dependent;
- upstream object;
- relation type;
- scope;
- provenance;
- epistemic state;
- version;
- owner/reviewer;
- downstream exposure;
- correction/supersession;
- review trigger.

Change in an upstream object may trigger bounded downstream review.

It does not automatically rewrite downstream conclusions.

# 12. RF-J — Current Civil State Synthesis

Multiple state-producing systems require a reusable current-state synthesis layer.

System state includes, where applicable:

- identity;
- owner/domain;
- capabilities;
- unresolved state;
- multidimensional maturity;
- interfaces;
- dependencies;
- validation;
- provenance;
- uncertainty;
- freshness;
- temporal change.

The synthesis is a view over source-owned state, not sovereign truth.

# 13. RF-K — Abstraction-Depth and Civilisational Levelling

Version, evidence maturity and recursive architectural depth are distinct.

A system must be auditable against frozen general requirements.

Its warranted abstraction level is contiguous completeness through those requirements.

At civilisation scale:

Civilisational Level
= minimum verified abstraction level across required systems.

The development frontier is formed by systems preventing transition to the next common layer.

Dependency topology then determines development order.

# 14. RF-L — Recursive Self-Development of the Development Mechanism

The development architecture itself can become an object of its own developmental process.

M_n
→ Use(M_n)
→ DetectGap(M_n)
→ Develop(M_n)
→ M_(n+1).

This relation family is supported by one preserved architectural-level event, not by long-run operational evidence.

It must therefore remain experimental.

# 15. Important Finding

These relation families are **not automatically twelve abstraction layers**.

Several are likely components of the same layer.

For example:

- correction and provenance are tightly coupled;
- bounded authority and participant consequence may belong to one constrained-action layer;
- dependency ownership and persistent dependency representation may represent successive abstractions;
- State Map and AL levelling clearly arise later in the preserved experimental chronology.

Therefore numbering must be based on dependency between abstractions, not on the order in which headings appear here.

# 16. Candidate Precedence Relations

The current evidence supports at least these precedence constraints:

RF-A precedes RF-B/C because function and consequence must be identifiable before their boundaries can be audited.

RF-B/C precede or co-develop with RF-D because correction/termination acts on consequential bounded functions.

RF-D supports RF-E because learning requires review/correction events to preserve.

RF-A–E support RF-F because recursive self-application requires a grammar worth applying.

RF-G depends on identifiable functions/capabilities and boundaries.

RF-H depends on development/state change becoming an explicit object.

RF-I depends on RF-G because dependency records require dependency/ownership semantics.

RF-J depends on RF-H + RF-I + maturity/validation representations.

RF-K depends on RF-J plus frozen abstraction requirements.

RF-L depends on the development mechanism being represented sufficiently to apply its own methods to itself.

# 17. Non-Linear Structure

The evidence therefore suggests a **partially ordered abstraction structure**, not necessarily a single naturally occurring ladder.

A practical AL ladder may still be constructed by grouping relation families into cumulative audit layers.

But that ladder must preserve the partial-order dependencies rather than pretending every relation historically appeared in a perfectly linear sequence.
