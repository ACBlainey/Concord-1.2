## Purpose

This audit compares the graduated CWA module with its primary Fractal Contextual Wrappers source and the wider source family reopened during PMEDG development.

This case requires special care because several apparent portable innovations were subsequently shown by source recovery to already exist elsewhere in Concord. They are therefore not new principles. The back-propagation need is primarily **source consolidation**: return source-recovered architecture to the primary contextual-wrapper representation so future readers do not repeat the same extraction deficit.

## CWA-BP-01 — Precedence Resolution Router consolidation

The primary source correctly identifies precedence as unresolved and says explicit conflict/priority rules are required.

Wider source resolution found substantial existing Concord mechanisms across Functional Priority, Protective Authority, Constitutional Emergency, Judiciary, bounded jurisdiction and externality architecture.

Portable CWA integrates these as a **Precedence Resolution Router (PRR)** rather than inventing a universal winner hierarchy.

**Decision:** INCORPORATE as a source-family routing interface.

## CWA-BP-02 — Decision-object decomposition

Apparent actor/context conflicts may contain several different decision objects with different legitimate functional owners.

> **Apparent Actor Conflict May Be Multiple Decision Objects**

**Decision:** INCORPORATE.

## CWA-BP-03 — Authority-topology separation

Portable development distinguishes reporting, competence, responsibility, decision jurisdiction, protective authority, functional priority, review and escalation.

This prevents expertise, organisational rank or protective capability from silently becoming general authority.

**Decision:** INCORPORATE as conflict-resolution clarification.

## CWA-BP-04 — Permission-before-authority gate

Source recovery from Fractal Permission Architecture showed that a legitimate function may require only bounded permission rather than authority.

> **Functional Permission ≠ Contextual Authority**

> **Permission to Use ≠ Authority to Control**

**Decision:** INCORPORATE into the primary contextual-wrapper representation as an explicit interface to the existing permission architecture.

## CWA-BP-05 — Function-derived / minimum necessary permission

Recovered source chain:

**Legitimate Function → Genuine Functional Need → Reasonably Necessary Interaction → Minimum Necessary Permission → Function-Bounded Use → Function Completion / Basis Ends → Permission Terminates**

The primary wrapper source contains contextual permission but under-represents this detailed mechanism.

**Decision:** INCORPORATE by reference and compact semantics; do not duplicate the full Fractal Permission Architecture.

## CWA-BP-06 — Permission provenance and action specificity

Portable development records that permission may derive from law, owner/steward rule, contract, relationship, cultural convention, contextual inference or emergency necessity, and that one permitted action does not imply another.

**Decision:** INCORPORATE as a wrapper legibility requirement where permission ambiguity is material.

## CWA-BP-07 — Explicit non-inheritance / relational access

Blind testing sharpened the rule that nested contexts do not automatically inherit every parent permission/restriction, and physical reachability is distinct from normative access.

> **Nesting ≠ Automatic Rule Inheritance**

> **Reachability ≠ Permission**

**Decision:** INCORPORATE.

## CWA-BP-08 — Monotonic protection / clearance chains only when explicitly established

Some domains legitimately define additive/monotonic clearance relationships; others do not.

Portable development prevents a wrapper from inferring universal monotonic inheritance merely from nesting.

**Decision:** INCORPORATE as an interface safeguard.

## CWA-BP-09 — External-resolution discipline

Where CWA detects a conflict but no legitimate precedence rule/resolver is established, it must preserve:

**UNKNOWN / DISPUTED / REQUIRES EXTERNAL RESOLUTION**

rather than manufacture a winner.

**Decision:** INCORPORATE.

## CWA-BP-10 — Responsibility continuity during overlap/emergency

Temporary priority or emergency action must not erase responsibility, review or provenance across overlapping contexts.

**Decision:** INCORPORATE.

## CWA-BP-11 — Termination residual-state check

Ending a context should inspect residual permissions, capabilities, credentials, data, processes and temporary authority rather than merely declare reversion.

**Decision:** INCORPORATE as an operational/failure-mode improvement.

## CWA-BP-12 — Representation reconciliation

Human-readable, machine-readable and operational representations should not silently diverge. Where discrepancy exists, record and reconcile it rather than assuming one representation is reality.

**Decision:** INCORPORATE.

## CWA-BP-13 — Context-sensitive boundary legibility

Not every context transition is primarily spatial or requires identical notice. Legibility should be proportionate to material change, risk and participant relation.

**Decision:** INCORPORATE as clarification.

## CWA-BP-14 — Explicit ESCP source-resolution safeguard

CWA development itself twice demonstrated ESCP:
1. precedence looked locally unresolved until wider Concord source resolution recovered multiple mechanisms;
2. function-derived permission looked newly discovered until Fractal Permission Architecture recovered the mechanism and even the driveway example.

**Decision:** INCORPORATE an explicit source-resolution safeguard into the primary wrapper architecture.
