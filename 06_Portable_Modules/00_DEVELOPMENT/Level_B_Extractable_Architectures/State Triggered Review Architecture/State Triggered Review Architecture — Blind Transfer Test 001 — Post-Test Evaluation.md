### 5.2 Predicted pressure with novel detail

The evaluator supplied useful specific detail inside predicted pressure areas:

1. **Explicit IMPOSSIBLE and RETIRED states.**  
   P43 predicted stale/impossible lifecycle pressure; the response sharpened this into missing state-vocabulary entries.

2. **Explicit ROUTING-UNRESOLVED state.**  
   P45 predicted ownership/routing pressure; the response identified a concrete missing state already used conceptually in v0.1.

3. **Minimum uncertainty algebra.**  
   P44 predicted compound uncertainty pressure; the response gave concrete cases: A AND UNKNOWN, A OR UNKNOWN, NOT UNKNOWN and A AND DISPUTED.

4. **Materiality declaration/evaluation object.**  
   P47 predicted materiality-interface pressure; the response proposed a more explicit host-supplied interface.

5. **Validation evidence / authority provenance interface.**  
   This is closely related to P45/P47 and the capability pressures, but the specific request for validation/authority provenance is novel detail.

6. **Dependency reconciliation interface.**  
   P45 and P47 anticipated boundary pressure; the response sharpened it into handling conflicting source states.

7. **Recurrence/equivalence determination record.**  
   Predicted event-overmatching/materiality pressure was refined into a specific disputed-equivalence routing need.

8. **Privacy-result interface.**  
   P48 predicted successful privacy-preserving signalling; the evaluator additionally noted that the interface itself lacks a defined portable result form.

9. **Cascade parentage/default controls.**  
   P46 predicted cascade/de-duplication pressure; the response sharpened this into minimum defaults/depth/materiality-gate concerns.

10. **Ownership-resolution request/tracking.**  
    P45 predicted owner distinction/routing pressure; the response identified missing lifecycle tracking for resolution.

11. **Ordering relation provenance/confidence.**  
    P24/P25 predicted external ordering pressure; the response sharpened the external relation requirements.

12. **Mandatory or bounded stale-trigger self-review.**  
    P43 predicted lifecycle pressure; the response noted that v0.1 only makes stale-trigger review optional.

These details are preserved as evidence-supported revision candidates without being counted as retrospectively predicted.

### 5.3 Wholly unpredicted findings

No wholly unpredicted finding appears to challenge the mechanism.

Two broader observations are worth preserving but do not require separate mechanism expansion:

- the evaluator judged the invariant set to be the strongest part of STRA;
- ownership resolution recurred across both the direct ownership-gap case and cascade control.

These are interpretive observations rather than new scored predictions.

## 8. Revision decision

> **REVISION TYPE: BOUNDED SPECIFICATION / INTERFACE CLARIFICATION**

Authorise v0.2 to address only the evidenced pressure.

Do not:

- expand STRA into a general dependency system;
- make STRA owner of domain materiality;
- create general governance authority;
- absorb memory/provenance systems;
- absorb event reconciliation;
- make privacy interfaces require raw data;
- claim external empirical validation beyond this blind architectural transfer test.

## 9. Required v0.2 changes

v0.2 should minimally:

1. add or formally support IMPOSSIBLE, RETIRED and ROUTING-UNRESOLVED outcomes/states;
2. define minimum compound uncertainty semantics;
3. formalise a host-supplied materiality evaluation interface;
4. distinguish trigger-definition owner, trigger evaluator, substantive review/action owner and ownership-resolution route;
5. add validation evidence/authority provenance to relevant input interfaces;
6. define bounded reconciliation handoffs for conflicting dependency/state inputs;
7. define recurrence/equivalence determination handoff;
8. define a privacy-preserving bounded-result interface;
9. strengthen cascade parentage, duplicate/cycle and materiality-gate semantics;
10. define ownership-resolution request/tracking;
11. require provenance/confidence/status on externally supplied material ordering relations;
12. require bounded review/backstop for long-lived WATCHING triggers.

These changes should preserve the v0.1 kernel.
