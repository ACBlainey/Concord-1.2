# 4. Functional Priority architecture

The strongest immediately relevant source is **Functional Priority and Protective Authority**.

It explicitly states:

> **Priority of Function ≠ Superiority of Participant**

and gives the example that an operator's activated safety function can take priority over a manager's ordinary production function concerning operation of an unsafe machine.

The source does not say:

**Operator > Manager**

It says, in effect:

**Activated Safety Function > Ordinary Production Function for the affected decision**

The authority remains decision- and function-bounded.

The same source explicitly states:

> **Coordination Authority ≠ Absolute Control**

and defines **Protective Authority** as a bounded capability to refuse, interrupt, modify, escape, warn or legitimately intervene where necessary to protect fundamental rights, immediate safety or another sufficiently high-order ethical constraint.

It further states:

> **Protective Authority Need Not Be Delegated by the Authority It Constrains.**

This matters to contextual precedence because some constraints arise from a different legitimate source than the authority being constrained.

---

## 5. Escalation rather than rank override

Functional Priority provides a concrete conflict-handling sequence.

For an unsafe machine:

**Operator Activates Safety Stop**  
→ **Production Function Pauses**  
→ **Manager Activates Escalation / Coordination Function**  
→ **Relevant Technical / Safety Function Evaluates**  
→ **Remediation**  
→ **Competent Function Determines Safety Condition**  
→ **Machine Cleared or Remains Restricted**  
→ **Production Resumes When Legitimate**

This is not a simple hierarchy of persons.

It is a state-dependent routing of decision authority according to function.

The source explicitly states:

> **Reporting Authority ≠ Decision Competence**

and:

> **Management Competence ≠ Universal Domain Competence**

This suggests that some apparent precedence problems should be decomposed into **which function owns which decision component**, rather than solved by selecting one globally superior actor or context.

# 6. Explicit functional priority

The source contains a dedicated **Functional Priority** section.

Where legitimate functions conflict, it states that a priority architecture is required.

Its example is:

**Production Direction**

versus

**Immediate Safety Stop**

Under defined dangerous conditions:

> **Immediate Safety Stop > Production Direction**

But the source immediately constrains the interpretation:

> **Safety Function Has Priority Concerning This Decision**

not:

> **Safety Participant Is Superior to Production Participant**

and therefore:

> **Functional Priority ≠ Personal Hierarchy**

This is directly relevant to CWA.

It establishes that precedence can be:

- contextual;
- conditional;
- function-specific;
- decision-specific;
- temporary;
- non-transferable to unrelated questions.

# 8. Protective and emergency state transitions

The source's Protective Authority branch is:

**Potential Serious Harm / Rights Violation**  
→ **Protective Threshold Reached**  
→ **Protective Authority Activates**  
→ **Minimum Necessary Refusal / Stop / Escape / Warning / Intervention**  
→ **Immediate Risk Managed**  
→ **Escalation to Relevant Competent Function**  
→ **Review / Remedy / Learning**

Its Emergency Escape branch explicitly includes:

**Fire / Immediate Serious Threat**  
→ **Ordinary Context Superseded**  
→ **Immediate Protective Autonomy**  
→ **Disregard Conflicting Ordinary Instructions Where Necessary**

This provides a real precedence relation for a defined class of circumstances.

It should not be generalised into “emergency always wins.” It is a conditional protective rule tied to immediate serious threat and minimum necessary action.

# 9. Constitutional Emergency architecture

**Constitutional Emergency V2** supplies another important precedence layer.

Its foundational rule is:

> **Emergencies change operational priorities. They do not change constitutional principles.**

It also states:

> **Emergency authority may accelerate constitutional action, but it must not deepen constitutional sovereignty.**

and:

> **Crisis must never manufacture authority.**

The governing sequence remains:

**Constitution → Emergency Authority → Emergency Action**

rather than emergency becoming an independent source of legitimacy.

The framework further establishes **Minimum Constitutional Deviation**:

> the smallest temporary constitutional deviation capable of effectively addressing the immediate threat.

This adds a higher-level constraint to CWA emergency composition:

**Emergency Operational Priority** may change, while **constitutional invariants remain controlling**.

Again, this is not a universal context-precedence algorithm. It is a source-backed rule for emergency constitutional contexts.

# 10. Cross-boundary externality architecture

The **Cross-Boundary Externality Recognition and Responsibility Mechanism (CBERRM)** contributes another important anti-precedence error.

It distinguishes:

- jurisdiction;
- remedy;
- authority;
- standing to raise;
- authority to decide.

It states:

> **Standing to Raise ≠ Authority to Decide.**

and:

> **The absence of shared jurisdiction does not erase the externality. Equally, the existence of an externality does not create jurisdiction.**

Possible jurisdiction states include internal, shared/agreed, overlapping, disputed, no shared jurisdiction, voluntary coordination, optional mediation, emergency-contact-only, Peaceful Distance/no-further-process, and unknown.

This means some CWA conflicts should not be forced into a precedence result at all.

The correct result may instead be:

**Conflict / Externality Detected**  
→ **Jurisdiction Mapped**  
→ **No Legitimate Resolver or Shared Authority Established**  
→ **UNKNOWN / DISPUTED / BOUNDED COORDINATION / NO FURTHER PROCESS**

Thus:

> **Problem existence ≠ authority to resolve it.**

# 11. Safe Spaces and bounded legal variation

The Safe Spaces / Special Jurisdictions architecture adds a layered normative model.

It distinguishes:

- common constitutional requirements;
- fundamental sentient rights;
- common civilisational interoperability requirements;
- legitimate local variation;
- voluntary special conditions;
- individual choice.

It explicitly rejects local variation as a means of overriding fundamental sentient rights and treats meaningful consent, exit, externalities and constitutional permissibility as constraints.

This supports the original wrapper paper's preliminary precedence observation that legitimate local contextual variation operates **inside** wider protected constraints.

The boundaries between some layers are explicitly left for further development.

# 13. Resulting precedence architecture

The wider search shows that the Concord does **not** rely on one simple rule such as:

- newest context wins;
- smallest context wins;
- most local context wins;
- emergency always wins;
- highest-ranked participant wins;
- most restrictive rule wins.

Instead, existing Concord architecture resolves different conflict classes through different legitimate bases.

A provisional source-derived routing model is:

### A. Protected invariant applies

If a contextual rule conflicts with an applicable fundamental right or constitutional invariant:

**Protected Constraint → bounds contextual rule/authority**

The participant holding the protected right does not become hierarchically superior.

### B. Immediate serious harm / protective threshold applies

**Protective Function Activates → minimum necessary protective action → conflicting ordinary function may pause → competent resolution/review**

### C. Functional competence conflict

Decompose the decision.

**Identify Decision Component → Identify Legitimate Function → Identify Competent Function → Apply Function-Bounded Priority → Escalate unresolved components**

### D. Constitutional emergency

**Constitution remains controlling → emergency operational priorities may change → minimum sufficient temporary deviation → review → termination/reversion**

### E. Explicit local/domain precedence exists

Apply the legitimate established rule within its scope.

### F. Legal/constitutional dispute within legitimate jurisdiction

Route to the applicable adjudicative architecture.

### G. Cross-boundary or disputed jurisdiction

Map jurisdiction and responsibility separately. Do not manufacture jurisdiction from harm, standing, technical capability or desire for remedy.

### H. No legitimate precedence or resolver established

Preserve:

**UNKNOWN / DISPUTED / REQUIRES EXTERNAL RESOLUTION**

# 14. What remains unresolved

The wider search materially reduces the apparent gap but does not establish a single universal precedence algorithm.

The remaining question is better stated as:

> **Can the existing family of source-backed precedence routes be formalised into a general conflict-classification and routing grammar without falsely collapsing distinct legitimacy bases into one hierarchy?**

That is different from the earlier question:

> “What universal rule decides which context wins?”

The wider Concord suggests that the second formulation may itself be too crude.

The architecture appears to favour **functional decomposition and legitimate routing** over universal winner selection.

# 15. Implication for CWA

CWA should probably not contain a universal precedence hierarchy.

Instead, it should contain a **Precedence Resolution Router** that asks:

1. What exactly conflicts?
2. Is there an applicable protected invariant?
3. Has a protective/emergency threshold legitimately activated?
4. Which functions own the conflicting decision components?
5. Is an explicit domain/context priority rule already established?
6. Is there a legitimate resolver/adjudicator with jurisdiction?
7. Is jurisdiction shared, overlapping, disputed or absent?
8. Can the conflict be decomposed rather than globally ranked?
9. What minimum temporary action is justified while resolution occurs?
10. What remains UNKNOWN or DISPUTED?

This router would not itself decide substantive law.

It would identify the legitimate source of precedence where one exists and preserve unresolved state where one does not.
