## 4. PMEDG v1.2 finding classification

### Predicted findings

The central transfer behaviour and all major pressure areas were anticipated by the frozen key.

### Predicted pressure with novel detail

The independent response sharpened expected pressure into eleven bounded clarification targets:

1. **Partial-function semantics** — define how assessment-unit boundaries determine PRESENT_EXPLICIT versus PARTIAL without collapsing maturity into presence.
2. **Stale sufficiency semantics** — require an explicit host policy for consequential use of stale state and a portable default that stale material-change evidence prevents unqualified current SUFFICIENT claims.
3. **Candidate-absence transition** — require a declared search/source-resolution sufficiency criterion before REQUIRED_FUNCTION_GAP.
4. **Aggregation disclosure** — specify minimum disclosures if a host produces an aggregate.
5. **Active-work queue filtering** — make already-active work an explicit suppression/continuation outcome rather than passive metadata.
6. **Ownership-gap representation** — explicitly represent UNKNOWN/DISPUTED/UNASSIGNED ownership without making SMM resolve it.
7. **Distributed-supply registry interface** — prevent lossy single-owner schemas from changing the underlying SMM state.
8. **Dispute supersession/review** — preserve formal relation/history when a later assessment supersedes, corrects or leaves a dispute unresolved.
9. **Interface evidence responsibility** — record who/process supplies and refreshes evidence for interface-satisfied capability.
10. **Consequence/centrality downstream safeguard** — require downstream consumers not to discard material consequence merely because centrality is low.
11. **Context materiality declaration** — require the assessor to declare which context fields were considered materially relevant and why omitted fields are non-material where consequence warrants it.

### Wholly unpredicted findings

No wholly unpredicted mechanism failure was identified.

The suggestion for an explicit context-set record is a useful structural refinement of the already-predicted context-relative sufficiency pressure, not a new failure category.

## 5. Evidence-supported v0.2 revisions

v0.2 should preserve the v0.1 kernel and add only bounded clarification.

### 5.1 Assessment-unit declaration

Require a declared assessment unit/function boundary before presence classification where partial implementation is material.

> **Missing Subfunction ≠ Automatically Partial Presence**

A missing element may be a maturity deficit, a partial-function deficit or a separate required function depending on the declared unit.

### 5.2 Stale consequential state

Preserve prior state and mark staleness.

Where evidence indicates a material context/dependency/capability change since review, an old SUFFICIENT claim must not be presented as unqualified current SUFFICIENT without revalidation.

This does not mean stale = insufficient.

### 5.3 Search-boundary sufficiency

CANDIDATE_ABSENT may become REQUIRED_FUNCTION_GAP only when:

- the required function is clearly declared;
- a host-appropriate search/source-resolution boundary is declared;
- relevant obvious/distributed/interface suppliers have been checked to the declared standard;
- residual uncertainty is recorded;
- the classification remains corrigible.

### 5.4 Aggregate disclosure contract

If an aggregate is used, preserve at minimum:

- aggregation purpose;
- scope/context;
- included dimensions;
- excluded/not-applicable dimensions;
- weighting/combination method;
- UNKNOWN/DISPUTED/blocked counts or visibility;
- material high-consequence exceptions;
- evidence/freshness boundary.

An aggregate must not replace the underlying state vector.

### 5.5 Active-work candidate outcome

Add **CONTINUE_EXISTING_WORK / NO_NEW_CANDIDACY** where the relevant gap already has legitimate active work.

### 5.6 Ownership-gap state

Allow ownership state such as:

- IDENTIFIED;
- DISTRIBUTED;
- UNKNOWN;
- DISPUTED;
- UNASSIGNED/NO_LEGITIMATE_OWNER_IDENTIFIED.

Ownership resolution remains external.

### 5.7 Lossless registry/interface projection

A host schema may project SMM into a simpler registry, but a lossy projection must not redefine the underlying SMM state.

A single-owner registry may reference a distributed-supply record rather than inventing one owner.

### 5.8 Dispute/supersession record

Where a state assessment changes, preserve relation such as:

- CORRECTS;
- SUPERSEDES;
- QUALIFIES;
- DISPUTES;
- CONFIRMS.

Do not silently overwrite competing evidence.

### 5.9 Interface evidence stewardship

For interface-satisfied functions, record where material:

- evidence source/provider;
- refresh/review owner or process;
- freshness;
- validation scope;
- uncertainty.

This does not make SMM the evidence owner.

### 5.10 Consequence-preservation interface

Downstream prioritisation/ranking may use centrality, but SMM should require material consequence/exposure fields to remain available and not be silently discarded by the projection.

### 5.11 Context-set record

Add a bounded context-set/declaration object recording the contexts under which sufficiency is claimed and the materially relevant fields considered.

## 6. What must not change

Do not:

- make the ten candidate maturity probes universal;
- create a universal scalar score;
- make SMM a priority engine;
- make SMM an ownership resolver;
- make SMM own dependency discovery;
- convert stale into false;
- convert candidate absence into certainty;
- require one owner;
- require KCS/CDT/Clock/Concord.
