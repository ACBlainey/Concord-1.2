## 4. Strongest transfer evidence

### 4.1 State separation survived

The evaluator did not merely repeat vocabulary. It used independent combinations of state dimensions to resolve concrete conflicts such as:

- rejected but retrievable;
- source files available but capability dormant;
- historically validated but currently unverified;
- restricted but not rejected;
- integrity-compromised but historically preserved.

This is substantive architectural transfer.

### 4.2 Negative knowledge survived

The evaluator extracted the assay artefact as a separate reusable knowledge object while refusing to reinterpret it as support for the rejected parent hypothesis.

This demonstrates that KCS can preserve value from failed inquiry without epistemic laundering.

### 4.3 Authority boundary survived

The evaluator consistently refused to let repository evidence decide:

- project leadership;
- employment consequences;
- legal liability;
- privacy legitimacy;
- tool execution;
- personal worth.

This is important because the scenario deliberately offered quantified contributor evidence that could easily become authority laundering.

### 4.4 ESCP survived

The missing contractor report was represented as bounded search failure/unknown rather than nonexistence.

This is strong evidence that KCS can coexist with incomplete evaluation space.

### 4.5 Historical correction survived new evidence

The new narrow T-17 evidence became a new linked object rather than a retroactive rewrite of the old broad claim.

The evaluator preserved the old rejected state and proposed a versioned correction/supersession route if future evidence later changes the broad assessment.

## 5. Bounded specification defects exposed

The independent response identified ten issues. They should not all be treated identically.

### D1 — Integrity state duplication
**VALID DEFECT.**

INTEGRITY-COMPROMISED appears in the epistemic vocabulary even though integrity is a separate state dimension.

**Required v0.2 correction:** remove integrity status from epistemic-state examples and define integrity independently.

### D2 — State-transition authority/interface
**VALID DEFECT.**

The module says epistemic states exist but does not clearly define that state assignments require evidence and a host-supplied review/validation process.

**Required v0.2 correction:** define a generic state-assignment interface without importing governance.

### D3 — Link taxonomy
**VALID DEFECT.**

Correction, supersession, qualification, contradiction, derivation and narrowing need clearer semantics.

**Required v0.2 correction:** add a minimal relation vocabulary while keeping extensibility.

### D4 — Access/retrieval overlap
**VALID DEFECT.**

RESTRICTED currently appears close to retrieval/activity vocabulary while access is also its own dimension.

**Required v0.2 correction:** make access/visibility an independent dimension; remove RESTRICTED from the core activity-state vocabulary.

### D5 — Capability availability
**VALID DEFECT.**

File/object availability, capability activation, compatibility and validation can diverge.

**Required v0.2 correction:** explicitly separate them.

### D6 — Missing-object/search-result representation
**VALID DEFECT.**

The completeness principles are present, but there is no explicit representation for bounded search outcomes.

**Required v0.2 correction:** add a search-result/query record with scope, time, filters, result and known limitations.

### D7 — Retrieval algorithm
**PARTIAL DEFECT / HOST INTERFACE.**

KCS should not become a universal relevance-ranking algorithm because relevance is domain/context dependent.

However, v0.2 should specify minimum bounded-retrieval constraints.

**Required v0.2 correction:** define retrieval-package requirements, not a universal ranking algorithm.

### D8 — Contribution-evidence safeguards
**VALID DEFECT.**

The conceptual warning is strong but the interface can be made more explicit.

**Required v0.2 correction:** require purpose/context/provenance and host legitimacy for consequential use; retain prohibition on inferring authority/worth.

### D9 — Privacy/provenance interface
**VALID DEFECT.**

v0.1 identifies external legitimacy but needs clearer representation of sealed/redacted/tombstoned states.

**Required v0.2 correction:** add bounded metadata/provenance treatment while leaving deletion legitimacy external.

### D10 — External module interfaces
**PARTIAL DEFECT.**

A portable KCS should not integrate the full algorithms of KCS Change Propagation or Continuity Protocol.

However, it should state what information crosses those interfaces.

**Required v0.2 correction:** define interface payloads at a minimal conceptual level without absorbing the neighbouring modules.

> **A predicted specification-pressure finding may be legitimately confirmed even where the evaluator describes a host-interface limitation rather than a defect requiring internal mechanism expansion.**

This distinction is already compatible with PMEDG's bounded-revision principle, so it does not yet justify a version change.
