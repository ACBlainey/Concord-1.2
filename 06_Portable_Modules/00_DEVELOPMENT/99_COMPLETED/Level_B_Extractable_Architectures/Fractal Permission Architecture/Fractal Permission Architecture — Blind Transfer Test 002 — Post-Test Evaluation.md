## 4. Remaining bounded findings

The tester identified eight issues. None requires a new architectural primitive.

### 4.1 Conflict-routing fallback
Clarify that FPA does not define the universal competent authority. When no resolution route is known, preserve UNKNOWN/CONFLICT state and avoid irreversible action where reasonably possible until an appropriate route is established.

### 4.2 Emergency handover
Clarify that handover/acceptance by an authorised successor may terminate or transform the original emergency permission; continuing action requires a continuing or new basis.

### 4.3 Machine/normative divergence
Clarify that remediation ownership is external. Interim restrictions should be proportionate to consequence and confidence, not blanket denial where uncertainty is low-consequence.

### 4.4 Anti-bureaucracy operational threshold
Do not invent a universal numerical threshold. Clarify a lightweight/formal escalation heuristic using consequence, contestability, automation, cross-context reach, persistence, irreversibility and audit need.

### 4.5 Delegation versus credential sharing
Explicitly separate normative delegation from credential transfer/impersonation. Credential sharing cannot itself create delegation authority and may independently violate external security rules.

### 4.6 Function/competence predicates
Already correctly externalised. Clarify that unresolved material predicate disputes should produce UNKNOWN/REVIEW rather than actor-defined expansion.

### 4.7 Implied-convention evidence
Clarify candidate evidence sources: published local rule, stable practice, communicated convention, prior consistent interaction, or another externally recognised source. Explicit markings/restrictions can narrow an otherwise applicable convention, subject to external legitimacy.

### 4.8 Interim conflict posture
Add a non-universal safety principle: where unresolved permission conflict affects an irreversible or high-consequence action, avoid treating the most permissive claim as controlling merely because it enables action; preserve the conflict and route review.

## 5. Convergence across tests

BTT-001 used a physical community fabrication workshop.

BTT-002 used distributed collaborative research/cloud infrastructure.

Despite materially different objects, actors, risks and implementation mechanisms, both tests independently preserved the same architectural invariants:
- capability ≠ permission;
- access ≠ single permission;
- function-bounded scope;
- nested/context-specific scope;
- path/action distinction;
- delegation must be independently grounded;
- emergency authority is bounded and terminable;
- rule provenance matters;
- conflict representation does not create precedence;
- technical/machine state does not establish legitimacy;
- permission formalisation should be proportionate.

The repeated result suggests the extracted architecture is portable at specification level rather than merely fitted to the original source domain.
