## Portable core

**Observed Local Omission → Resolve Architectural Unit → Resolve Legitimate Scope → Abstract Tested Relation → Build Relevant Source-Grounded Family → Test External/Distributed Satisfaction → Test Interface Adequacy → Reach Diagnostic Closure → Classify → Preserve Search Scope and Uncertainty**

Core safeguards:

- **Document ≠ necessarily System**
- **Missing locally ≠ missing architecturally**
- **Named neighbour ≠ adequate interface**
- **Similar Topic ≠ Same Architectural Family**
- **External Capability ≠ Interface Satisfaction**
- **Future Reference ≠ Current Architectural Dependency**
- **Diagnostic Closure ≠ Functional Satisfaction**
- **Do Not Classify the Workflow Before Decomposing the Missing Function**

## ESCP compliance

AUR preserves bounded evaluation-space discipline. C7 means no adequate owner/capability was established within the resolved relevant family and recorded search scope; it does not mean a capability exists nowhere. Both tests preserved UNKNOWN where required.

## Standalone boundary

AUR is a pre-gap diagnostic architecture. It does not perform the entire CRADP cycle, redesign systems, grant authority, determine substantive ethical/legal correctness, prove every source has been recovered, or turn dependency into permission/legitimacy.

## Validation limits

Graduation authorises a standalone portable release at specification level. It does not establish universal empirical validity, universal superiority, complete cross-domain validation, legal/regulatory/safety certification, or proof that every possible architectural family can be resolved.
