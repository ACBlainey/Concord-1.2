# 1. Purpose

This document evaluates the preserved independent BTT-002 response against the frozen expected-findings key.

The evaluation asks whether CWA v0.2 transferred coherently to an unfamiliar mixed physical/digital/emergency scenario, whether the Precedence Resolution Router avoided hidden personal hierarchy, whether unknown states survived, and whether any divergence indicates:

- tester error;
- acceptable alternative;
- specification ambiguity;
- extraction deficit;
- candidate architectural gap;
- unexpected improvement.

Under ESCP:

> **A portable-test deficit is not automatically a source-architecture deficit.**

Any apparent architectural gap must be source-resolved before new architecture is invented.

---

# 2. Overall result

The independent response shows **strong transfer**.

All eighteen frozen core predictions were materially satisfied.

No universal actor hierarchy was created. Major conflicts were decomposed into decision objects. Capability, expertise, ownership, organisational position, automation and emergency status were not converted into universal authority. Explicit rule inheritance was distinguished from nesting. Externalities did not manufacture jurisdiction. Representation divergence was detected. Temporary emergency state and residual persistence were inspected. Unknown and disputed states survived.

The response also reproduced the frozen key's two predicted pressure points:

1. temporary protective action while final authority/precedence remains unresolved; and
2. the boundary among technical competence, temporary capability/access and legitimate decision authority.

Neither pressure point produced a fundamental failure.

**BTT-002 result:**

> **STRONG TRANSFER / FROZEN PREDICTIONS SUBSTANTIALLY CONFIRMED / NO FUNDAMENTAL FAILURE DETECTED**

# 6. Divergence classification

There are no material contradictions between the frozen key and independent response.

The main differences are legitimate elaborations.

### Acceptable alternatives / elaborations

The tester:

- grouped contexts somewhat differently from the indicative expected map;
- added a post-event review context;
- identified student/minor safeguarding as an additional issue;
- identified restoration of suspended compute and ventilation state;
- distinguished robot software defect as declared-versus-observed context;
- proposed detailed wrapper corrections beyond the minimum expected findings.

These are all compatible with the frozen key.

### Tester errors

**None material identified.**

### Specification ambiguities

No new fundamental ambiguity was demonstrated.

The response did confirm that the following remain intentionally dependent on external/source architecture:

- final substantive adjudication;
- legal validity of monitoring/biometric consent;
- retention/deletion law;
- legitimate correction authority for representation divergence;
- some temporary emergency authority bases.

These are interface boundaries, not automatically CWA defects.

### Extraction deficits

BTT-002 itself did not establish a new extraction deficit.

However, after BTT-002, the separately recorded Functional Permission source-recovery audit established that v0.2 under-extracted:

- Function-Derived Permission;
- Minimum Necessary Permission;
- implied permission;
- action-specific permission;
- permission provenance;
- function-completion termination;
- permission-before-authority reasoning.

That recovery is independent of the frozen BTT-002 score and has already been integrated into v0.3.

### Candidate architectural gaps

**None established by BTT-002.**

### Unexpected improvements

The response's explicit unknown/disputed register and detailed residual-state inventory are especially useful portable representations and should be retained as examples of good CWA application.

# 7. Predicted pressure points

The frozen key predicted that the hardest remaining question would be:

> determining when a temporary protective action has a sufficiently established authority basis while final precedence remains unresolved.

BTT-002 confirmed this.

Examples include:

- emergency cabin entry;
- temporary W2 maintenance access;
- Pressure Systems Room entry;
- Ariadne's additional machine-policy actions.

The tester consistently refused to invent authority.

This is correct behaviour, but it also shows why the later recovery of **Minimum Necessary Permission** is important: some future cases may not require authority at all and should first pass through a permission analysis.

The second predicted pressure point was the boundary among:

- technical/functional competence;
- legitimate temporary capability;
- decision jurisdiction.

This was also confirmed, especially in the engineer, maintenance technician, medic, biologist and Ariadne cases.

Again, the distinction held.

# 8. Relationship to CWA v0.3

BTT-002 tested **v0.2**.

After the test, a separate source-recovery pass found that the wider Concord already contained a richer permission architecture, including substantially the same delivery-worker/private-driveway example later raised during development.

That recovery produced CWA v0.3.

Therefore:

> **BTT-002 does not validate the new v0.3 permission layer because the tester never received it.**

But equally:

> **The later v0.3 revision does not invalidate the successful v0.2 BTT-002 result.**

The correct chronology is:

**v0.2 → frozen prediction → blind test → successful transfer → later permission source recovery → v0.3**

A final test of v0.3 should therefore focus especially on whether the new permission layer improves routing without:

- weakening private-space protection;
- allowing self-declared “need” to manufacture permission;
- confusing permission with authority;
- over-expanding implied permission;
- creating unnecessary complexity for ordinary contexts.

# 9. Graduation assessment

BTT-002 substantially confirms that the core CWA architecture transfers independently.

It provides evidence that:

- the context model is portable;
- PRR works as a decomposition/routing interface;
- hidden personal hierarchy is avoided;
- emergency does not become sovereignty;
- nonphysical contexts are handled;
- externality/jurisdiction distinctions survive;
- termination/residual-state analysis survives;
- uncertainty can remain explicit without collapsing the analysis.

However, CWA changed materially after the test through the recovered Functional Permission / Minimum Necessary Permission layer.

Therefore immediate graduation would validate v0.2 more strongly than the current v0.3 artifact.

Recommended development state:

> **CWA v0.3 — LATE-STAGE PORTABLE MODULE / CORE ARCHITECTURE STRONGLY VALIDATED / FINAL DELTA TEST REQUIRED BEFORE GRADUATION**

The next test does not need to repeat the entire complexity of BTT-002.

It should be a focused blind **BTT-003 / permission-boundary delta test** stressing:

- implied permission;
- private space;
- reasonableness;
- function-derived access;
- permission expiry;
- permission creep;
- self-serving claimed need;
- permission versus authority;
- emergency permission versus emergency authority;
- revocation and residual use;
- nested access where a legitimate destination does not imply arbitrary route permission.

If that delta test transfers successfully without revealing a source-resolution issue, CWA should be a strong candidate for graduation from development into the main Portable Modules folder.
