# Sketch Idea — Empirical Testing Programme for Concord Systems and Modules

**Status:** SKETCH / UNTESTED / NON-CANONICAL
**Origin:** V1.2a backlog.

## Problem
Much Concord development is logical, architectural, comparative or simulated. A systematic question remains: which systems and modules can be subjected to empirical testing?

## Sketch
Create a testing taxonomy that distinguishes:
- logical consistency tests;
- adversarial paper scenarios;
- simulation;
- historical replay;
- human-participant experiments;
- AI-agent experiments;
- heterogeneous AI replication;
- prototype operational trials;
- longitudinal observation;
- and eventual real-world deployment evidence.

## Development Questions
Which claims are actually empirical? What outcome variables and falsification criteria apply? Which tests require ethical safeguards? Which systems can only be indirectly tested before deployment?

## Possible Output
A Concord Empirical Test Register linking each system/module to claims, test type, evidence, falsification condition, replication status and unresolved uncertainty.

## Provenance
Formalised from `empirical testing.txt`.
